# ThinkVantage 0.7.0 功能补全与代码审计

日期：2026-11-16，Asia/Hong_Kong。

用户请求是完善软件并在完成后审计、修复必要问题。提供的 0.5.3 功能差距报告是参考材料，其中优先级、接口草案和长期硬件扩展不是用户逐项要求，也不是本次已经执行的验收。工作基于当前 0.6.0 静态 Qt 代码，发布版本为 0.7.0。

## 审计中修复的必要问题

实现后进行了跨模块独立审计，并在修复后复核。以下包括原报告提出并经当前源码确认的问题，以及新功能整合中发现的问题。

- 刷新率预览从设置前到确认/恢复结束保持同一硬件写锁；操作 token、显示器接口身份与完整模式共同判断归属。外部修改或设备断连时旧恢复不覆盖新状态。
- GUI 的刷新率总超时关闭 stdin 请求恢复，不直接 kill 承担恢复责任的 worker；预览确认重新计算预算。
- 音频一次操作绑定端点 ID/flow/role；亮度一次操作绑定 WMI InstanceName；Windows 电源模式绑定同一 AC/DC 配置侧。
- 全局 probe 失败具有 `ok:false` 和非零退出码；GUI 旧快照标记过期，禁止以旧证据继续写入。写入进程崩溃、非法输出、超时或读回失败标记 `unknownOutcome`，停止队列并只读核对。
- 电池 bridge 内层错误及部分成功数据保留；未知值不补零。GPU 列表异常不再被当作无人占用。
- 实机验证发现 GPUInfo 会向 stdout 写调试日志；已把原厂调用放入私有子进程，捕获整个流并只接受明确的结果帧，公开 CLI 保持单个 JSON。崩溃或超时仅令占用查询不可用。
- GPU OC 与 ITS 之间以状态等待替代固定延迟；分别记录原 OC 参数和 ITS 恢复、读回及失败。
- 供电未知值不再冒充电池供电；条件写在锁内比较旧值和供电状态，旧场景不越过新的电源上下文。
- 自动化执行与主窗/快捷面板共享忙状态；每项动作后等待新的 probe，不能按旧快照连续写入。
- 手动充电请求仅在成功后解除一次性任务，失败不丢失原模式；首次恢复读取不可用时保留恢复标志。
- 缓存过期时退出仍可发送条件恢复；保存失败独立提示，已经持久化原模式的任务可尝试紧急恢复。
- 退出期间停止普通场景；手动充电完成后继续办理已经请求的退出。
- UI/托盘 smoke 与截图均禁止执行用户真实自动化；外部文本固定按 PlainText 显示。
- Core Audio 回调跨线程排队，析构先 detach；音量与拓扑事件分开去抖，避免每个音量通知重建端点订阅。

## 验证方法与证据

构建运行 `scripts/build.ps1 -Package`，包含 MSVC Release 编译、五组 CTest、静态依赖检查和带重链接材料的便携包。离线测试覆盖协议、界面增量更新/过期状态、厂商字段及进程列表、刷新率事务决策、场景去重/覆盖/配置校验/充满任务状态机。

`tests/cli_contract.py` 检查 JSON schema、退出码、未知命令、参数数量、非法整数/范围、未知 ID 和锁内条件不匹配；所有请求均不能通过写入前提。`tests/integration.py` 使用默认模式，仅执行读取及被拒绝的请求，比较前后设置。原生 UI/tray smoke 验证 6 页、32 个主窗控制与 9 个快捷控制，保存截图并检查布局。

生成证据位于 `research/v070-*`、`docs/screenshots-v070` 和 `build/static-release/Testing/Temporary/LastTest.log`；这些是工作区开发产物，不自动当作跨机型验证。最终实际执行结果另记于 `docs/VALIDATION.md` 的 0.7.0 段。

## 尚未验证或未实现

本次不切换真实硬件档位，不启用 GPU OC、不模拟实际插拔供电、不完成一次真实的 100% 充电周期，也没有执行硬件写入故障注入。自动化的状态机单测与条件拒绝检查不能代替这些场景。自启动开关未实际写入注册表测试。

刷新率恢复依赖 worker 存活；操作系统崩溃、外部强制终止 worker 或原生显示调用永久挂起，仍不能保证恢复，挂起时退出可能继续等待。当前硬件写锁使用 Local 命名空间，没有新增跨用户/跨 Windows 会话的硬件所有权方案。

多显示器枚举/目标选择、DDC/CI、音频设备路由、传感器历史、CPU/GPU 遥测、通用热键/OSD，以及风扇、功耗、MUX、任意充电阈值等硬件扩展不在本版实现范围。一次操作绑定目标身份不等于完整多屏支持。原厂可选组件仍采用现有本机版本提取方式，不代表完成广泛版本发现或跨机型适配。
