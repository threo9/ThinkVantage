# 截图 R01–R05 核对及修复

用户请求为检查截图意见，并修复确有必要的问题。截图中的建议作为待核实意见；以下结论来自当前源码检查和回归，不把建议本身当作已证明的故障。

| 意见 | 核对结果与修复 |
|---|---|
| R01 排队后设备目标变化 | 成立。手动请求入队保存目标、requestId 和事件代际，锁内重新核对音频端点、亮度实例及显示源/面板身份；不符返回 target_changed 且不写入。事件使缓存过期，跨事件的旧 probe 不发布为 fresh。当前采用整份快照的保守失效，未拆逐域 probe。 |
| R02 延迟供电处理清除较晚手动覆盖 | 成立。同步记录供电上下文，手动请求前读取当前供电；场景执行不再清除覆盖。供电代际独立于上次执行档位，快速 AC→DC→AC 也会重新评估，避免仅凭最终布尔值漏掉转换。 |
| R03 忙碌时取消/暂停被忽略 | 成立。暂停即时关闭普通场景并撤销待执行普通动作；取消保存为待处理意图与任务中的 cancelRequested，当前写入及核对结束后串行条件恢复，不 kill 承担恢复责任的 worker。 |
| R04 默认验证旧包 | 成立。默认版本/路径/标签从 CMake 推导，发现 Python 后才清理 PATH，创建输出目录；校验真实 EXE 版本与 manifest hash，记录源码与构建来源，拒绝指定的旧 0.6.0 包。 |
| R05 提权固定 7 秒等待 | 成立。随机 token 通道中完成准备、原任务恢复、锁转移、就绪与提交握手；旧实例保持到接管确认，失败则取消交接并尝试收回锁。交接期间阻止旧窗口和托盘发起新手动写入。 |

新增回归包括设备目标变化、旧读取代际、两种供电/手动顺序、快速供电往返、启动过程中的持久取消，以及本地套接字交接的成功/启动失败/断管/放锁后回收。交接成功测试实际等待至少 8 秒才准备完成，超过原 7 秒窗口；使用独立测试实例域，不触发 UAC，也不写硬件。

最终 0.7.1：7/7 CTest、22 项 CLI 检查、默认 verify-smooth 入口均通过；原生主窗 6 页/32 控件、托盘 9 控件通过。旧 0.6.0 包已做启动前拒绝检查。构建与验证来源均明确为提交基础加本地修改，不把修复包冒称为旧提交的纯净构建。证据见 research/static-v071-completion.json、research/v071-cli-contract.json 和 build/static-release/Testing/Temporary/LastTest.log。

本地命名管道测试需要宿主允许创建命名管道；受限沙箱中的 access denied 不能当作握手协议失败。真实 UAC 确认、带真实 Top Up 的提权恢复、设备热插拔后的实际写入未在本轮执行。提升进程永久卡在原生构造且系统拒绝终止时仍可能无法收回正常锁，此时保留原窗口并报告错误，不能承诺强制夺回所有权。
